# Сертификаты для доверия TLS

Хакатонный контур MAX (`platform-api2.max.ru`) использует сертификат, выданный национальным удостоверяющим центром Минцифры (`Russian Trusted Sub CA`). Операционные системы и Docker-образы ему по умолчанию не доверяют. Проверку сертификата отключать нельзя (`-k`, `verify=false`, `NODE_TLS_REJECT_UNAUTHORIZED=0`), а в системное хранилище компьютера сертификат устанавливать не нужно.

## Что хранится здесь

Публичные корневые сертификаты в файлах `*.crt` (это не секрет). Файлы `*.pem` в репозиторий не попадают: они запрещены проверками и `.gitignore`.

## Как добавить сертификат (поток K-05a)

1. Скачайте корневой сертификат с официальной страницы Минцифры «Сертификаты безопасности» на Госуслугах (`gosuslugi.ru/crt`; убедитесь, что открыт официальный сайт).
2. Проверьте отпечаток независимо от места скачивания, например по второй официальной странице:
   ```bash
   openssl x509 -in russian_trusted_root_ca.crt -noout -subject -issuer -fingerprint -sha256
   ```
3. Положите файл сюда как `certs/russian_trusted_root_ca.crt` и запишите отпечаток и источник в результат потока.
4. Убедитесь, что запрос проходит с проверкой сертификата (токен не выводите):
   ```bash
   set -a; source .env; set +a
   curl -s --cacert certs/russian_trusted_root_ca.crt -H "Authorization: $MAX_BOT_TOKEN" "$MAX_API_BASE_URL/me" | python3 -m json.tool
   ```

## Как использовать в приложении

Сертификат подключается только процессу приложения:

- Node.js: переменная окружения `NODE_EXTRA_CA_CERTS=$MAX_CA_CERT_PATH` (добавляет сертификат к стандартным, не заменяя их);
- Docker: файл копируется в образ, `NODE_EXTRA_CA_CERTS` задаётся в окружении сервиса;
- другие языки: собственный набор доверенных сертификатов клиента HTTP, а не системный.
