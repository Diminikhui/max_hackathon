# 0003. Бот, выданный организаторами, хакатонный контур MAX и доверие TLS

- Статус: принято
- Дата: 2026-09-20
- Участники: @Diminikhui

## Контекст

В ADR-0002 команда решила создать бота самостоятельно. Организаторы хакатона ответили, что токен выдан ими и работает на хакатонном контуре `https://platform-api2.max.ru` (в документации MAX описан боевой контур `platform-api.max.ru`). Запрос `GET /me` возвращает бота «Хакатон МАХ 214» с ником `t214_hakaton_max_bot`. Сертификат контура выдан национальным удостоверяющим центром Минцифры, которому по умолчанию не доверяют операционные системы и Docker-образы; в примере организаторов проверка отключена ключом `-k`.

Первая попытка проверки токена не прошла по двум причинам: использовался боевой адрес и токен был скопирован без первого символа.

## Решение

1. Используем бота, выданного организаторами. Собственного бота не создаём; пункт 4 ADR-0002 заменён.
2. Ник бота: `t214_hakaton_max_bot` (не меняется). Название: «Хакатон МАХ 214».
3. Адрес API задаётся переменной `MAX_API_BASE_URL` (по умолчанию `https://platform-api2.max.ru`) и не вшивается в код.
4. Проверку TLS не отключаем (`-k`, `verify=false`, `NODE_TLS_REJECT_UNAUTHORIZED=0` запрещены; проверка в CI).
5. Корневой сертификат НУЦ Минцифры хранится в `certs/` как публичный `*.crt`, подключается только процессу приложения (`NODE_EXTRA_CA_CERTS`) и в системное хранилище компьютеров не устанавливается. Отпечаток проверяется по независимому официальному источнику.
6. Токен хранится только в локальном `.env`. При копировании токена сверяйте длину: потеря первого символа даёт ошибку `Invalid access_token`.
7. Проверка подключения: `GET {MAX_API_BASE_URL}/me` возвращает ник бота.

## Альтернативы

- Ключ `-k`: отклонён, отключает проверку сертификата и делает трафик уязвимым для подмены.
- Установка сертификата в системное хранилище: отклонена, расширяет доверие для всех приложений компьютера.
- Собственный бот: отклонён, требует верифицированного профиля и модерации до 48 часов, а кейс предполагает работу на выданном токене.

## Последствия

- Потоки MAX (K-05a, K-21b, K-22a) работают на хакатонном контуре; отличия от боевого фиксируются в K-05c.
- Docker-образ содержит публичный сертификат, проверяющий воспроизводит запуск без установки сертификатов у себя.
- Поведение контура при публикации вне хакатона нужно перепроверить (этап 5).
