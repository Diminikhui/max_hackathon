# 0002. Решения команды: направления, название, бот

- Статус: принято; пункт 4 (бот) заменён [ADR-0003](0003-issued-bot-and-hackathon-contour.md)
- Дата: 2026-09-19
- Участники: @Diminikhui

## Контекст

Эталонные чеклисты обязанностей и пакеты правил делаются вручную по каждому ОКВЭД-направлению, поэтому набор направлений определяет объём работы на критическом пути ядра. Кейс требует узкий приоритетный сегмент и явного пользователя.

## Решение

1. **Направления ядра:**
   - A — общепит, ОКВЭД 56;
   - B — автосервис, ОКВЭД 45.2;
   - C — розничная торговля, ОКВЭД 47.

   Направление A — на критическом пути: его чеклист и пакет правил нужны для сдачи ядра. Направления B и C идут параллельно и не блокируют сдачу.
2. **Регионы:** Москва и Республика Татарстан.
3. **Название продукта:** «Пульс».
4. **Бот:** команда создаёт бота сама через профиль MAX для партнёров. Параллельно направляется запрос организаторам: организаторы обещают каждой команде токен, а кейс предполагает работу с выданным токеном, поэтому нужно подтвердить, что собственный бот допустим. Ник бота после создания изменить нельзя; выбранный ник фиксируется в потоке K-05a.
5. **Сегмент:** владельцы микробизнеса и ИП с работниками без штатного бухгалтера и юриста.

## Альтернативы

- Швейное производство (ОКВЭД 14) вместо розничной торговли: более узкие производственные требования, но меньше охват. Заменено на розничную торговлю по решению команды.
- Ждать только токен организаторов: не требует модерации, но блокирует потоки MAX до ответа.

## Последствия

- Розничная торговля (47) шире и размытее по обязанностям, чем остальные направления: эталонный чеклист может получиться длиннее, при нехватке времени направление C сдвигается после сдачи ядра.
- Создание бота требует верифицированного профиля на платформе MAX для партнёров и модерации бота (до 48 часов по рабочим дням), это нужно начать сразу.
- Если организаторы потребуют использовать выданный токен, бот меняется без изменения кода: токен хранится в `.env`.
