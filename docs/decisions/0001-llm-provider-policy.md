# 0001. Допустимые ИИ-сервисы

- Статус: принято
- Дата: 2026-09-19
- Участники: @Diminikhui

## Контекст

Продукт работает с нормативными документами: ошибка модели может ввести пользователя в заблуждение. Кейс требует привязывать ответы к источникам, показывать основание и не выдавать предположение модели за официальный факт. Внешний иностранный ИИ недопустим, допустимы только GigaChat и локальная модель.

## Решение

1. Допустимые провайдеры: **GigaChat** и **локальная модель**. Другие внешние сервисы не используются.
2. Провайдер выбирается переменной `LLM_PROVIDER`: `template` (по умолчанию) / `gigachat` / `local`.
3. Режим `template` — детерминированный шаблон без ИИ. Продукт полностью работает в этом режиме и запускается без ключей.
4. Модель не определяет юридическую истину. Применимость правила вычисляется детерминированным механизмом; модель только извлекает структуру из документов и переформулирует уже вычисленный результат.
5. Ответ модели проходит строгую схему; при сбое или несоответствии схеме система откатывается на `template`.
6. Текст документов из внешних источников считается недоверенными данными и не может менять инструкции модели.
7. Ключи хранятся только в окружении; в репозитории — `.env.example` без значений.
8. Локальная модель подключается отдельным профилем Docker; вес модели не запекается в образ, чтобы сборка укладывалась в 5 минут.

## Альтернативы

- Внешние иностранные сервисы: недопустимы по условиям.
- Только локальная модель: тяжёлая для воспроизведения проверяющими.
- Только GigaChat: зависимость от ключа и сети при проверке. Резервный `template` снимает эту зависимость.

## Последствия

- Качество резюме в режиме `template` ниже; оценка качества по каждому провайдеру — в потоке K-19e.
- Условия и лимиты GigaChat проверяются в K-19b по официальной документации.
- Каждый новый провайдер обязан пройти те же контрактные тесты и схему ответа.
