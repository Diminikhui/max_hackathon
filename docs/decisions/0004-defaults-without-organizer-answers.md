# 0004. Решения по умолчанию, если организаторы не ответят

- Статус: принято
- Дата: 2026-09-20
- Участники: @Diminikhui

## Контекст

Три вопроса к организаторам остаются без ответа, и команда не ждёт его. Чтобы работа не стояла, для каждого вопроса выбрано решение по умолчанию с оценкой риска.

## Решение

### 1. Собственный API мини-приложения

Собственный API **не заявляем**. Кейс называет его необязательным и не даёт за него баллов; заявленный API требует `DATA-API.yaml`, тестовых учётных записей и автоматических проверок, которые могут не пройти.

- Методы мини-приложения описываем в OpenAPI 3.1 (`contracts/miniapp-api.yaml`, поток 2-01b) как внутреннюю документацию.
- В README отдельный раздел: «Внутренние методы мини-приложения (не заявляются как собственный API)» с перечнем методов и тестовыми данными.
- Поток 2-16 (заявка API) не выполняется; запускается только при подтверждении, что бэкенд мини-приложения считается собственным API.

### 2. Подготовка этапа 4 до объявления результатов

Готовим в отдельных ветках. Сданную версию (тег `online-submission`) не меняем; в `main` этап 4 сливается только после объявления результатов (поток 4-00).

### 3. Время дедлайна

Точное время неизвестно. Считаем крайним сроком **29.09.2026 23:59 МСК**, на сутки раньше официального 30.09. Сдаваемый пакет (поток 3-11) готовим к этому времени. Версию фиксируем тегом и commit hash.

## Альтернативы

- Заявить API: даёт формальное соответствие, но добавляет работу и риск непрохождения обязательных проверок без выигрыша в баллах.
- Ждать ответов: блокирует потоки, зависящие от решения.
- Считать крайним сроком 30.09 без запаса: риск не успеть при неточном времени.

## Последствия

- Если проверяющие сочтут бэкенд собственным API, часть баллов за документацию и интеграцию может быть потеряна; риск снижают внутренний OpenAPI, README и тестовые данные.
- Если организаторы запретят подготовку этапа 4 заранее, эта работа уместится только в период после результатов (до финала 29.10).
- Запас в сутки сокращает время разработки, но снимает зависимость от неизвестного времени дедлайна.
