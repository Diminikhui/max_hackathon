# 0005. Стек и раскладка репозитория

- Статус: предложено
- Дата: 2026-09-24
- Участники: @Diminikhui

## Контекст

Около сорока потоков волны 1 ([roadmap](../roadmap.md)) стартуют после K-01a и K-02 и работают параллельно, каждый в своей зоне файлов. Им нужны единый язык, единая раскладка и общий способ сборки, иначе потоки разойдутся уже в первые часы. Кейс рекомендует JavaScript и React; мини-приложение MAX строится на MAX UI и MAX Bridge, которые рассчитаны на React.

## Решение

### Стек

| Слой | Выбор | Кто подключает |
|---|---|---|
| Язык | TypeScript в строгом режиме, ES-модули | K-01a |
| Среда выполнения | Node.js 24 LTS (`.nvmrc`, `engines`) | K-01a |
| Менеджер пакетов | pnpm (workspace), версия зафиксирована в `packageManager`; включается через `corepack enable` | K-01a |
| Сборка серверных пакетов | `tsc -b` с project references; каждый пакет собирается в свой `dist/` | K-01a |
| Мини-приложение | React + Vite; MAX UI и MAX Bridge | K-01a (каркас), K-05b и 2-01a (MAX UI, Bridge) |
| База данных | PostgreSQL; миграции — SQL-файлы в `packages/storage/migrations/` с префиксом потока | K-10a/b/c |
| Контракты | JSON Schema в `contracts/`, проверка — Ajv | K-02 |
| Тесты | Vitest | K-01b |
| Линтер и форматирование | ESLint и Prettier | K-01b |
| Контейнеры | Docker Compose | K-07 |

Потоки выбирают библиотеки внутри своей зоны сами (HTTP-сервер, клиент Bot API, драйвер БД) и записывают выбор в «Результат» потока. Новый язык, среда выполнения или менеджер пакетов — только новым ADR.

### Раскладка

```text
contracts/            схемы и примеры контрактов, OpenAPI мини-приложения (K-02)
packages/domain/      доменная модель, порты, справочники ОКВЭД и регионов
packages/rules/       механизм применимости: условия, статусы, объяснение, загрузчик пакетов
packages/adapters/    источники профиля, требований и мер поддержки: real, fixture, synthetic
packages/classifier/  провайдеры ИИ (template, GigaChat, локальная модель) и классификатор
packages/storage/     схема БД, миграции, реализации портов хранилища
packages/services/    прикладные сценарии: профиль, перечень, уточнения, пересчёт
packages/metrics/     метрики продукта
packages/observability/ логи, трассировка, проверки здоровья
packages/security/    проверка initData, секреты, минимизация персональных данных
apps/bot/             бот MAX
apps/miniapp/         мини-приложение (React + Vite)
apps/miniapp-api/     HTTP API мини-приложения
apps/worker/          получение документов, планировщик уведомлений, отправка
certs/                публичные корневые сертификаты (*.crt)
data/rulepacks/       пакеты правил по направлениям и регионам
data/fixtures/        тестовые и модельные данные
docs/                 документация и решения
```

Один каталог верхнего уровня в `packages/` и `apps/` — один пакет workspace с именем `@max-hackathon/<каталог>`. Зоны потоков из roadmap (`packages/rules/conditions/`, `apps/bot/flows/onboarding/` и т. п.) — подкаталоги внутри `src/` соответствующего пакета: `packages/rules/conditions/` означает `packages/rules/src/conditions/`. Новые пакеты верхнего уровня не заводятся без изменения этого ADR: так раскладка остаётся такой, как её видят все потоки.

### Шаблон пакета

Пустые пакеты из K-01a и есть шаблон. Пакет в `packages/`:

- `package.json` — `"type": "module"`, `exports` указывает на `dist/index.js` и `dist/index.d.ts`, скрипт `build: tsc -b`;
- `tsconfig.json` — наследует `tsconfig.base.json`, `rootDir: src`, `outDir: dist`;
- `src/index.ts` — публичный вход пакета.

Приложение в `apps/` устроено так же, но вход — `src/main.ts`, запуск — `pnpm --filter @max-hackathon/<имя> start`. Мини-приложение — исключение: собирается Vite, `tsc` только проверяет типы.

### Зависимости между пакетами

Пакет подключает другой пакет двумя правками:

1. в `package.json`: `"dependencies": { "@max-hackathon/domain": "workspace:*" }`;
2. в `tsconfig.json`: `"references": [{ "path": "../../packages/domain" }]`.

Направление зависимостей: `apps/* → packages/services → packages/{rules, adapters, classifier, storage} → packages/domain`. `packages/domain` не зависит ни от одного пакета проекта. Циклы запрещены: `tsc -b` их не соберёт.

### Команды

```bash
corepack enable
pnpm install
pnpm build        # все пакеты и приложения
pnpm typecheck    # проверка типов без сборки мини-приложения
pnpm run clean    # удалить dist (у pnpm есть встроенная команда clean, поэтому через run)
```

## Альтернативы

- **JavaScript без TypeScript.** Кейс это допускает, но при сорока параллельных потоках типы контрактов — главная защита от расхождений между потоками. Отклонено.
- **Python или Kotlin для бэкенда.** Два языка удваивают инструменты и контракты; мини-приложение всё равно на React. Отклонено.
- **npm workspaces.** Нет строгой изоляции зависимостей: пакет может импортировать то, чего нет в его `package.json`, и это ломается в Docker. pnpm ловит это сразу. Выбран pnpm.
- **Монорепо-оркестратор (Turborepo, Nx).** Для 13 пакетов достаточно `tsc -b`: он собирает в порядке ссылок и пропускает неизменённое. Можно добавить позже без смены раскладки.
- **Мелкие пакеты на каждую зону потока** (`packages/rules-conditions` и т. д.). Около 70 пакетов и столько же `package.json`; зоны меняются чаще, чем границы модулей. Отклонено: зона — подкаталог.

## Последствия

- Потоки волны 1 начинают в готовом пакете: не нужно договариваться о сборке, модулях и именах.
- `packageManager` фиксирует pnpm 11; участникам нужен `corepack enable` или pnpm той же мажорной версии.
- CI, линтер, форматирование и тесты добавляет K-01b; Docker-образы — K-07. До их слияния проверка — `pnpm build`.
- TypeScript установлен версии 7. Если какой-то инструмент потока окажется с ним несовместим, поток фиксирует версию 5.x отдельным PR в корень с пояснением.
