# K-04a: доступ к ЕГРЮЛ/ЕГРИП для профиля

Проверено 25.09.2026 по опубликованным материалам ФНС. Исследуется только получение открытых сведений о ЮЛ и ИП для `CompanyProfile` v1. Фикстуры в `data/fixtures/k04a-model-profiles.json` — **модельные данные**, не ответы ФНС и не подтверждение существования организаций.

ФНС указывает стоимость годового обслуживания **150 000 ₽ за один реестр** и разового полного предоставления **50 000 ₽ за один реестр** на [странице порядка доступа](https://www.nalog.gov.ru/rn77/service/egrip2/access_order/). Это тариф на массовые сведения, а не на бесплатную выписку о конкретном лице. Перед расходами нужна повторная проверка актуальности условий.

## Формат и обновление

- Файловая интеграция: ZIP → XML в `windows-1251`; корни `EGRUL` и `EGRIP`, записи `СвЮЛ` и `СвИП`. Узел содержит ИНН/ИННФЛ и ОГРН/ОГРНИП; `ДатаВыг` — дата формирования файла, `ДатаВып` — дата состояния записи. Это описано в [модели взаимодействия ФНС](https://www.nalog.gov.ru/rn77/service/egrip2/egrip_vzayim/).
- Версии на дату проверки: ЕГРЮЛ **4.08**, ЕГРИП **4.07** действуют с 01.02.2026; старые 4.07/4.06 ФНС обещает выдавать до 22.01.2027. Источник — [страница интеграции ФНС](https://www.nalog.gov.ru/rn77/service/egrip2/). Парсер должен учитывать версию файла; пример XML на странице ФНС показывает лишь оболочку, не полный набор полей новой версии.
- Дневные выгрузки могут запаздывать; отсутствующие за день записи ФНС включает в последующие файлы. Более свежая запись по ОГРН/ОГРНИП **полностью заменяет** предыдущий узел `СвЮЛ`/`СвИП`, а не дополняет его. Источник — [модель взаимодействия ФНС](https://www.nalog.gov.ru/rn77/service/egrip2/egrip_vzayim/).
- С 2026 года различаются заявительные и отчётные ОКВЭД; основной код может смениться при поступлении данных Росстата. Процентные доли в публичных выписках не раскрываются. Источник — [пояснение ФНС об ОКВЭД](https://www.nalog.gov.ru/okved/). Следовательно, один `activity.okved_main` в v1 отражает видимый на дату выписки основной код, но не тип и долю кода.

## Поля для `CompanyProfile` v1

| Поле | Кандидат из ЕГРЮЛ/ЕГРИП | Граница |
| --- | --- | --- |
| `inn`, `entityType` | `ИНН` в `СвЮЛ` / `ИННФЛ` в `СвИП`; тип по реестру | Сверять ИНН с запросом и контрольную сумму. Не считать ввод пользователя официальным фактом до проверки. |
| `displayName` | Название ЮЛ | Для ИП это ФИО; не сохранять его в общие фикстуры, логи и телеметрию. В моделях ИП поле опущено. |
| `activity.okved_main`, `activity.okved_additional` | Коды из актуальной выписки | Сохранять дату выписки и первоисточник в `SourceRef`; не выдумывать основной код при его отсутствии. Тип ОКВЭД v1 не передаёт. |
| `location.region_code` | Регион адреса ЮЛ после разбора открытого адреса | Для ИП адрес проживания закрыт. Не выводить регион из первых цифр ИНН: это не надёжное текущее местонахождение. Для ИП нужен другой допустимый источник или заявленный факт. |
| `scale.msp_category`, `employment.headcount`, `tax.regime`, `licenses.has_any`, `sales.alcohol` | Не выводятся из ЕГРЮЛ/ЕГРИП как подтверждённые факты в этом исследовании | МСП, режим налогообложения и другие признаки требуют отдельных источников или уточнения у пользователя; отсутствие поля означает «неизвестно». |

Схема v1 допускает модельные данные через `CompanyProfile.isModel` и `SourceRef.isModel`. Для **реального** факта нужны `isModel: false`, `system` с именем ФНС, URL конкретного официального документа/записи, `retrievedAt` и дата состояния. Подписанную выписку и личные данные нельзя класть в репозиторий. Официальный статус или прекращение деятельности требуют отдельного согласованного ключа факта, если понадобятся движку правил.

## Пять модельных ИНН

[`data/fixtures/k04a-model-profiles.json`](../../data/fixtures/k04a-model-profiles.json) содержит пять профилей контракта v1 с разными ИНН: три ЮЛ (общепит, автосервис, торговля) и два ИП (общепит, автосервис). ИНН с нулевым префиксом сгенерированы для сценариев, контрольные цифры рассчитаны, но **ФНС по ним не опрашивалась**. Названия и факты вымышлены; все профили и источники имеют `isModel: true`. `kind: official` в модели означает только предполагаемое происхождение поля при будущей загрузке реальной выписки; `system: fixture:*` не является официальным источником.

## Передача K-12a

На текущем доступе честный `ProfileSource` может возвращать модельный fixture либо понятную ошибку недоступности реального источника. Для критерия K-12a «контрактные тесты на реальных ответах» нужен законно полученный набор выписок и подтверждённый способ их автоматического получения, либо предоставленные команде атрибуты подписки. Не превращать модельные профили K-04a в «реальные ответы» и не использовать недокументированные запросы веб-интерфейса как стабильный API. При подключении файловой интеграции дополнительно проверить XSD версий 4.08/4.07, кодировку, подпись/доверие к документу, обновление по ОГРН и задержки выгрузки.
