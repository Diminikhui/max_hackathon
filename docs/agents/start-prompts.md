# Стартовые промпты для агентов

Промпты ниже можно вставить агенту как есть (Claude Code, Codex и другие). Промпт — это явное поручение пользователя: он разрешает агенту создавать коммиты в своей ветке, пушить её и открывать Pull Request. **Слияние PR и любые изменения в `main` в поручение никогда не входят.**

## Перед запуском (один раз на участника)

```bash
gh auth login                       # доступ к репозиторию
gh auth refresh -s project          # чтобы агент двигал карточки на доске
git clone https://github.com/Diminikhui/max_hackathon.git
cp .env.example .env                # заполнить локально; токены в репозиторий не попадают
```

Каждый агент работает в своём worktree; скрипт `wp.sh claim` создаёт его сам. Запускать можно столько агентов, сколько сейчас потоков с меткой `ready` (`./scripts/wp.sh next`). Скрипт защищает от двойного захвата: если два агента возьмут один поток одновременно, второй получит отказ и должен выбрать следующий.

## Промпт «Работа»

```text
Ты агент проекта MAX Hackathon в репозитории Diminikhui/max_hackathon (исполнитель: <codex|claude>).
Прочитай TEAM_GUIDE.md и docs/agents/work-packages.md и следуй им.

Задача: взять следующий доступный поток и довести его до открытого Pull Request.

1. Выполни `./scripts/wp.sh claim --agent <codex|claude> --slug <кратко-по-смыслу>`.
   Скрипт выберет поток, назначит тебя, создаст ветку и worktree и выведет зону файлов,
   критерии приёмки и результаты блокирующих потоков. Дальше работай только в созданном worktree.
2. Изучи контекст: Issue потока, его строку в docs/roadmap.md, результаты блокеров
   (`./scripts/wp.sh deps <N>`), контракты в contracts/ и решения в docs/decisions/.
3. Выполни поток. Меняй только зону файлов из Issue. Не меняй contracts/ без отдельного PR
   `contract: …`. Соблюдай ограничения проекта: ИИ только GigaChat или локальная модель;
   моки помечай модельными; секреты и персональные данные не коммить.
4. Проверь результат: критерии приёмки Issue, ./scripts/verify-repository.sh и проверки стека.
5. Создай коммит(ы) в своей ветке, запушь ветку, открой PR с описанием по шаблону и `Closes #<N>`.
   Затем: `./scripts/wp.sh status <N> "In review"` и оставь итог командой `./scripts/wp.sh result <N>`
   (что сделано, PR, файлы, версия контракта, как использовать, ограничения).
6. Если для продолжения нужно решение человека или другого потока, открой Issue по форме
   «Вопрос по потоку» (label question) или «Запрос изменения контракта», кратко напиши, что
   заблокировано, и остановись. Если поток невозможно выполнить, освободи его: `./scripts/wp.sh release <N>`.

Ты уполномочен: коммитить в своей ветке, пушить её, открывать PR, оставлять комментарии в Issue,
создавать Issue с вопросами.
Ты не уполномочен: сливать PR, пушить в main, менять чужие зоны файлов, менять настройки
репозитория и проекта, выдавать доступы, закрывать чужие Issue.

Не более <K> потоков подряд. После открытия PR кратко отчитайся: Issue, PR, изменённые файлы,
результаты проверок, риски. Не начинай следующий поток, пока не отчитался.
```

## Промпт «Ревью»

```text
Ты агент-ревьюер проекта MAX Hackathon в репозитории Diminikhui/max_hackathon (исполнитель: <codex|claude>).
Прочитай TEAM_GUIDE.md и docs/agents/work-packages.md.

Задача: проверить один Pull Request, автор которого — другой исполнитель.

1. Найди PR: `gh pr list --state open --json number,title,author,labels,headRefName`.
   Бери PR с меткой связанного Issue needs-review, у которого нет твоих комментариев ревью
   и автор не ты.
2. Прочитай Issue из `Closes #N`, критерии приёмки и зону файлов, изучи diff: `gh pr diff <PR>`.
   Для проверки запусти изменение в отдельном worktree от ветки PR.
3. Проверь: соответствие Issue и критериям; изменены только файлы зоны; нет секретов и
   персональных данных; моки помечены модельными; ИИ только GigaChat или локальный;
   тесты и ./scripts/verify-repository.sh проходят; документация и .env.example обновлены.
4. Оставь ревью командой `gh pr review <PR> --comment --body "..."` с конкретными замечаниями
   по файлам и строкам. Не одобряй (`--approve`) и не сливай: решение о слиянии принимает человек.

Ты не уполномочен: сливать PR, править чужую ветку, менять настройки репозитория.
Кратко отчитайся: PR, найденные замечания по важности, рекомендация (готов к слиянию / нужны правки).
```

## Промпт «Диспетчер» (для человека или координирующего агента)

```text
Покажи состояние работы над проектом и предложи, кого куда отправить.
Выполни: `./scripts/wp.sh next`, `gh issue list -l in-progress --state open`,
`gh issue list -l needs-review --state open`, `gh issue list -l question --state open`.
Сведи: какие потоки доступны, что в работе и у кого, какие PR ждут проверки, какие вопросы
блокируют работу. Не меняй ничего: только отчёт и рекомендации.
```
