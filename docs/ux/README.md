# UX-сценарий «Пульса»: As-Is / To-Be и правила текстов

- Поток: 2-13. Статус: **на утверждении** — тексты считаются утверждёнными после слияния PR с ревью участника команды.
- Дата: 2026-09-29.
- Обозначения: **[факт]** — есть источник; **[гипотеза]** — нужно проверить интервью ([docs/problem](../problem/README.md), раздел 4).
- Каталог всех текстов бота с экранами и файлами кода — [texts.md](texts.md).

Документ для двух читателей: разработчика, который пишет новый экран бота или мини-приложения, и автора слайда «решение и сценарий» (поток 3-08b). Слайд собирается из разделов 1–4.

## 1. Позиционирование

**Одной фразой (для слайда):**

> «Пульс» в MAX по ИНН показывает, какие обязательные требования касаются вашего бизнеса, и сам пишет, когда в них что-то меняется. Бухгалтер ведёт ваши налоги — «Пульс» показывает остальное и не даёт пропустить изменения.

**Что «Пульс» не делает** — это часть продукта, а не оговорка мелким шрифтом:

| «Пульс» | Не «Пульс» |
|---|---|
| Сообщает, что обязанность или право есть, и почему это касается компании | Рекомендует действие: «вам выгоднее…», «оформите так…» |
| Даёт ссылку на официальный первоисточник в каждой карточке и уведомлении | Даёт юридическое заключение или консультацию |
| Помечает автоматический текст как автоматический | Выдаёт пересказ за текст закона |
| Честно говорит «недостаточно данных» и «вне покрытия» | Угадывает, чтобы перечень выглядел полным |
| Работает рядом с бухгалтером и поставщиками услуг | Заменяет бухгалтера, юриста или санитарного консультанта |

Формулировка для пользователя (приветствие, раздел «Что проверяется», FAQ):

> «Пульс» не заменяет бухгалтера и юриста. Он показывает, какие требования касаются вашей компании, и присылает изменения со ссылкой на первоисточник. Решение, что делать, остаётся за вами и вашими специалистами.

## 2. As-Is: как владелец кафе узнаёт о требованиях сейчас

Персонаж: владелец кафе в Москве или Татарстане, ИП или ООО, 3–10 работников, без штатного юриста. Сегмент — не меньше 10,4 тыс. субъектов МСП только по ОКВЭД 56.10 в двух регионах [факт, problem 2.1].

**Обязанности закрывают несколько исполнителей по частям** [гипотеза Г3, Г5]:

| Часть обязанностей | Кто закрывает | Что видит этот исполнитель |
|---|---|---|
| Налоги, отчётность в ФНС и СФР | бухгалтер на аутсорсе | только свою часть; санитарию и маркировку не ведёт |
| Онлайн-касса, маркировка | поставщик ККТ, интегратор | настройки кассы, а не перечень обязанностей |
| ХАССП, медосмотры, дезинсекция | санитарный консультант, подрядчик дезинфекции | свою услугу |
| Пожарная безопасность | подрядчик по договору | свою услугу |
| Охрана труда, СОУТ | внешний специалист или никто | свою часть, если он есть |
| Алкоголь, региональные ограничения | сам владелец | то, что сам нашёл |
| **Целостная картина и изменения** | **никто, кроме владельца** | — |

**Путь владельца сейчас:**

1. Открывает кафе и собирает обязанности сам: из советов знакомых, статей поставщиков решений, вопросов к бухгалтеру. У эталонного кафе команды 18 обязанностей с основаниями в актах Правительства, Роспотребнадзора, ФНС, Россельхознадзора, МЧС, ЕАЭС и региона [факт, problem 2.6].
2. Единого места со всеми обязанностями нет: ФГИС РОТ не фильтрует по ОКВЭД, у regulation.gov.ru вместо ОКВЭД — 60 укрупнённых сфер [факт, problem 2.4].
3. Изменений — около 725 проектов актов в месяц, из них для общепита значимых 1–2 [факт, problem 2.2]. Следить вручную владелец не может.
4. О новом требовании узнаёт поздно: от инспектора, из предписания или случайно [гипотеза Г4]. Проверки точнее (результативность 88%), дистанционных в 2026 году в разы больше [факт, problem 2.3, 2.5].

**Боли:** нет полной картины; нет сигнала об изменениях; язык актов не отвечает на вопрос «что это значит для моего кафе»; платные системы мониторинга рассчитаны на бухгалтера, а не на владельца.

## 3. To-Be: как это работает с «Пульсом»

Основной сценарий целиком проходит в боте MAX; мини-приложение дополняет его перечнем и карточкой, но без него сценарий не обрывается ([пилот](../pilot/scenario-and-metrics.md), раздел 2).

| Шаг | Что делает пользователь | Что отвечает «Пульс» | Время |
|---|---|---|---|
| 1. Вход | Нажимает «Начать» в боте или ссылку от партнёра («Мой бизнес», бухгалтер) | Одним сообщением: что делает бот и что нужен ИНН | секунды |
| 2. ИНН | Отправляет ИНН | Проверяет контрольную сумму; при опечатке объясняет, что исправить | секунды |
| 3. Профиль | Видит карточку «Это ваша компания?» — ОКВЭД, регион, категория МСП, источник | Нажимает «✅ Всё верно» или «✏️ Другой ИНН» | до минуты |
| 4. Перечень | Открывает «📋 Мой перечень» | Счётчики по пяти статусам, записи по разделам: применяется → недостаточно данных → требуется проверка → вне покрытия | сразу |
| 5. Уточнение | Отвечает кнопками на 1–4 вопроса («Есть ли работники?», «Продаёте алкоголь?») | После каждого ответа — какие статусы изменились; ответ помечен «по вашим словам» | 1–2 минуты |
| 6. Карточка | Нажимает номер записи | Статус, почему это касается компании, срок, дата проверки, первоисточник, пометка об автоматической обработке | сразу |
| 7. Изменение | Ничего не делает | Бот сам присылает «🔔 Изменение»: что стало применяться или перестало, было → стало, первоисточник | 1–2 раза в месяц |
| 8. Ранний сигнал | Может отключить | «📝 Проект изменения»: это ещё не действующая норма, нужна проверка | по мере появления |
| 9. Контроль | «🔔 Уведомления»: отключить всё или только ранние сигналы | Настройки действуют сразу | сразу |

**Что меняется для владельца:**

| As-Is | To-Be |
|---|---|
| Картина обязанностей собрана по частям у разных исполнителей | Один перечень по ИНН за несколько минут, каждая запись со ссылкой на акт |
| Об изменениях узнаёт от инспектора | Бот пишет сам, в мессенджер, который и так открыт |
| 700+ проектов в месяц — никто не читает | 1–2 значимых сообщения в месяц; молчание перекрывает ежемесячная сводка (2-18) |
| Текст акта без ответа «касается ли меня» | Статус и «почему» по фактам профиля |
| Неизвестно, всё ли учтено | Явные «недостаточно данных» и «вне покрытия» вместо ложной полноты |

**Сценарий демонстрации (для защиты, 2 минуты)** на модельных данных [K-28](../../data/fixtures/k28-README.md):

1. ИНН `1600000011` (модельное кафе в Казани без данных о работниках и алкоголе) → профиль → перечень с разделом «❔ Недостаточно данных».
2. «❔ Уточнить данные» → «Есть ли у вас работники?» → «Да» → «Перечень пересчитан: • Обязанность работодателя общепита (модельная запись): Недостаточно данных → Применяется».
3. «🏠 Меню» → «🔄 Другая компания» (PR #309) → ИНН `7700000016` (модельная кофейня в Москве) → «🧪 Показать пример изменения (модельное)» → показ новой записи «Новая обязанность: маркировка упакованной воды в Москве (модельная запись)», почему она касается компании, и уведомление с первоисточником.

Все данные демо модельные и помечены в интерфейсе; записи пакета `k28-model` не являются юридическими утверждениями.

## 4. Принципы текстов (микрокопирайтинг)

1. **Одно сообщение — одно действие.** В конце сообщения понятно, что делать дальше; действие — кнопкой, а не командой.
2. **Обращение на «вы»**, без канцелярита и без «уважаемый пользователь». Глагол вместо отглагольного существительного: «Отправьте ИНН», а не «Осуществите ввод ИНН».
3. **Ошибка объясняет, что исправить, и не винит.** «ИНН организации — 10 цифр, ИП — 12», а не «Неверный ввод». Техническая причина (код, стек, название сервиса) пользователю не показывается.
4. **Нет тупиков.** В каждом сообщении есть кнопка дальше или назад («↩️ В начало», «🏠 Меню», «← К перечню»). Непонятный ввод — короткая подсказка и те же кнопки.
5. **Не рекомендуем действие.** Запрещены «рекомендуем», «вам выгоднее», «необходимо сделать», «советуем». Разрешены «применяется», «требование стало применяться», «срок», «первоисточник».
6. **Честная неопределённость.** «Недостаточно данных» лучше уверенной ошибки. Пустой перечень всегда сопровождается фразой «Пустой перечень не значит, что требований нет».
7. **Первоисточник и пометка.** Каждая карточка и уведомление о требовании заканчиваются блоком «Первоисточник:» и строкой «ℹ️ Текст сформирован автоматически. Сверяйтесь с первоисточником.»
8. **Модельное — видно сразу.** Модельные данные помечаются в заголовке (`· МОДЕЛЬНЫЕ ДАННЫЕ`) и в подвале (`🧪 Модельные данные — не результат реальной интеграции.`). Кнопки демо начинаются с 🧪.
9. **Заявленное отдельно от официального.** Ответ пользователя всегда подписан «по вашим словам».
10. **Коротко.** Заголовок — одна строка с эмодзи-маркером; тело — до 5–7 строк на экран; списки длиннее 5 пунктов сворачиваются в «и ещё N». Лимит MAX — 4000 символов, подвал с пометкой не обрезается.
11. **Даты** — `25.09.2026`, время — `25.09.2026, 12:00 (МСК)`. Сроки — конкретной датой, а не «в ближайшее время».
12. **ПДн не повторяем без нужды.** ИНН показываем только на карточке подтверждения профиля; в уведомлениях и перечне — не показываем ([безопасность данных](../security.md)).

### Словарь

| Пишем | Не пишем | Почему |
|---|---|---|
| перечень | список, каталог, чеклист | «Пульс» — поток, не каталог (концепт, раздел 1) |
| требование, обязанность, возможность | норма, правило (в тексте для пользователя) | «правило» — внутренний термин пакета |
| применяется / не применяется | актуально / неактуально | один из пяти статусов контракта |
| недостаточно данных | неизвестно, ошибка | статус, а не сбой |
| требуется проверка | возможно, вероятно | статус требует проверки человеком |
| вне покрытия системы | не поддерживается | бот честно говорит о границах |
| первоисточник | источник, ссылка | официальный акт |
| по вашим словам | вы указали, заявлено | отличает заявленный факт от официального |
| проект изменения | новый закон | проект — ещё не норма |
| модельные данные | тестовые, демо, фейковые | правило TEAM_GUIDE, п. 9 |

## 5. Тексты ошибок: правила

| Ситуация | Что говорим | Кнопки |
|---|---|---|
| Ошибка ввода (ИНН) | что именно не так и как исправить; повтор подсказки о формате | ↩️ В начало |
| Не найдено | «Компания с таким ИНН не найдена в реестре малого и среднего бизнеса ФНС» + «это не значит, что номер неверный или что компании нет» (в реестре нет крупных, исключённых и недавно попавших в него компаний) + «Проверьте номер ещё раз или отправьте ИНН другой компании» | ↩️ В начало |
| Источник недоступен | «Не удалось получить данные» + когда повторить (через минуту / позже) | ↩️ В начало |
| Сохранение не удалось | что не сохранилось + то же действие ещё раз | та же кнопка |
| Устаревшая кнопка или шаг | «Это действие устарело» + текущее меню | меню |
| Непонятный текст | «Не понял сообщение» + что можно сделать | текущие кнопки |
| Нет компании | «Сначала укажите ИНН компании» | Ввести ИНН |
| Мини-приложение: вход не подтверждён | «Не удалось подтвердить пользователя. Откройте сервис из MAX и попробуйте ещё раз.» (`UNAUTHENTICATED`) | — |

Тексты общих ошибок API — каталог `ERROR_DEFINITIONS` в `packages/observability/src/errors.ts`; они соответствуют этим правилам.
