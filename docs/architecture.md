# Архитектура

## Цель MVP

Показать сквозной сценарий: профиль компании → документ из официального источника → определение влияния → фильтрация → уведомление в MAX → переход к первоисточнику.

## Предварительные компоненты

```text
Official sources
      |
      v
Ingestion and normalization
      |
      v
Document impact classifier
      |
      v
Policy matcher <---- Company profile
      |
      v
Notification queue
      |
      +----> MAX bot
      +----> MAX mini app
```

## Границы компонентов

- **Ingestion** получает документы, сохраняет источник и устраняет дубликаты.
- **Classifier** формирует структурированное описание воздействия; результат должен быть проверяемым.
- **Company profile** хранит только признаки, необходимые для MVP: ИНН, ОКВЭД, регион и размер.
- **Policy matcher** использует детерминированные правила для отбора релевантных документов.
- **Notifications** исключает повторы и хранит статус доставки.
- **MAX integration** изолирует Bot API и проверку данных мини-приложения от доменной логики.

Технологии, API-контракты и схема развёртывания фиксируются отдельными ADR после выбора стека.
