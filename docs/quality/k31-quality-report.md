## Сравнение с эталоном

**Не хватает в пакетах** (эталон → пакет):

- `a.tatarstan.alcohol-regional-restrictions`
- `a.tatarstan.energy-drinks-places`

Это ожидаемо: региональное дополнение «Татарстан» — отдельный поток K-17d (#208, ещё не взят). Следствие для пользователя: кафе в Казани (`k28-cafe-kzn`) сейчас получает только федеральные записи; по эталону ему также положены «требуется проверка» по местам продажи энергетиков и «недостаточно данных» по региональным ограничениям алкоголя. Исправлять в зоне K-31 нельзя: записи добавляет K-17d.

**Есть только в пакете:** `a.fed.before-first-employee`, `a.fed.sick-persons-food-work-ban`. Добавлены в K-17a по решению проверки #171 (см. `review.note` эталона). В эталон их не переносили; при следующем обновлении эталона стоит добавить, чтобы сравнение снова было «один к одному».

**Покрытие (`coverage`):** пакет A — 10 `full`, 11 `partial`; эталон — 9 `full`, 12 `partial`. Разница целиком из-за состава записей выше; у 19 общих записей `coverage` совпадает.

Проверенные инварианты (все выполнены):

1. Записи чужого направления — только `not_applies`: автосервис и магазин не получают обязанностей общепита, кафе — автосервиса.
2. Запись с `coverage: partial` не даёт уверенного `applies` — не выше `needs_review` (K-15a).
3. Безусловная по ОКВЭД запись своего направления никогда не `not_applies`.

Выборочная ручная сверка отдельных пар:

- `k28-cafe-msk × a.fed.before-first-employee` → `not_applies`: работники уже есть, обязанность «до первого работника» не нужна — верно.
- `k28-cafe-msk × a.fed.alcohol-strong-license` → `not_applies`: продаёт только пиво — верно.
- `k28-cafe-kzn` — 7 × `insufficient_data` с `missingFactKeys` `employment.has_employees` / `sales.alcohol`: уточняющие вопросы задаются, а не «не применяется» — верно.
- `k28-cafe-bad-data` — записи о работниках `needs_review` из-за некорректного значения `"да"`, а не уверенный ответ — верно.
