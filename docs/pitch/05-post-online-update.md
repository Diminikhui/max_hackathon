- Дата сверки: 29.09.2026.
- Точка сравнения: README из PR #278, commit `cb45ae1` от 28.09.2026.
- Текущее основание: `main` перед финальной фиксацией онлайн-сдачи.

Финальный тег онлайн-сдачи на дату отчёта ещё не создан. Поэтому документ не называет текущий SHA окончательным: перед экспортом PDF команда должна подставить сдаваемый SHA и повторить чеклист из `docs/submission.md`.

## Что обновить в презентации

1. На слайде 8 говорить «основной сценарий проверен в web и mobile MAX на SHA `7fbaef7`» и повторить прогон на финальном SHA.
2. На слайде 11 оставить mini app отдельной строкой: оболочка и запуск реальны, продуктовый API ещё не собран.
3. В ограничениях считать Татарстан покрытым существующим пакетом; не использовать старую фразу «регион не отмечен в каталоге».
4. Отдельно проговорить, что демо-изменение и компании модельные, хотя транспорт и контур уведомлений реальные.
5. Не называть ЕГРЮЛ/ЕГРИП частью текущего runtime: адаптер реализован, но в сборку процесса не подключён. GigaChat подключён только для пересказа «Простым языком» за флагом `BOT_FEATURES=explain`, в сдаваемой конфигурации он выключен; для классификации документов ленты он не подключён.
6. Указать, что состояние бота хранится в PostgreSQL, но инфраструктура остаётся одним VPS без резервирования.
7. Про «тройное сообщение» говорить точно: это были три ответа на три быстрых нажатия одной кнопки, а не тройная доставка уведомления; исправлено в PR #349.

## Не изменилось

- Детерминированные правила, а не ИИ, решают применимость требований.
- Каждая карточка и уведомление содержат первоисточник и пометку об автоматической обработке.
- Реальные изменения пакетов проходят проверку человеком; модельный триггер нужен только для короткой демонстрации.
- Mini app не обязателен: весь проверяемый сценарий проходит в боте.
- Нагрузочная, юридическая и длительная эксплуатационная проверка остаются за пределами MVP.
