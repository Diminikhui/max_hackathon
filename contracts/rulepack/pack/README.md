# Формат пакета правил

[`pack.schema.json`](pack.schema.json) задаёт единицу публикации правил. Версия `packVersion` — положительное целое число внутри устойчивого `packId`; `contractVersion` соответствует контрактам v1. `owner` отвечает за содержание, `source` указывает происхождение пакета, `publishedAt` — время публикации версии, `validity` — период её действия. `isModel: true` означает модельные данные, которые нужно так и показывать пользователю.

`requirements` — непустой список записей [`Requirement v1`](../../v1/requirement.schema.json). Каждая запись содержит встроенное поле `condition`, которое дополнительно проверяется [схемой условий K-15a](../conditions/condition.schema.json). Встроенное условие и есть связь записи с проверяемым правилом; отдельного реестра условий и неоднозначных ссылок на него нет. `basis[].url` каждой записи указывает на источник правового основания, а `source` — на происхождение данных записи.

## Правила для загрузчика и CLI-валидатора K-15c

JSON Schema проверяет форму отдельных полей. Перед публикацией загрузчик также должен проверить:

1. `packId`, `packVersion` и `contractVersion` каждой записи равны полям пакета; `id` записей уникальны внутри пакета.
2. `validity.from <= validity.to`, если обе границы заданы. Даты действия записей, если есть, согласованы с периодом действия пакета.
3. `isModel` пакета, `source.isModel` пакета и `source.isModel` записей согласованы. Модельный пакет нельзя выдавать за реальный.
4. Новая версия одного `packId` увеличивает `packVersion`; устойчивый `Requirement.id` сохраняется для той же нормы.

Пример [`examples/model-cafe.json`](examples/model-cafe.json) полностью модельный и не содержит юридических утверждений. Для проверки загрузите схемы из `contracts/v1/`, `contracts/rulepack/conditions/` и эту схему в Ajv 2020 с `ajv-formats` и `strictRequired: false`; затем валидируйте пример по `$id` схемы пакета.
