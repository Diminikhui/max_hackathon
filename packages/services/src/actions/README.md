# Очередь действий

`ActionQueueService` строит очередь поверх результата `ChecklistService`:

1. берёт только требования со статусом `applies` и непустым `deadline`;
2. получает календарную дату из срока;
3. назначает приоритет относительно даты расчёта `asOf`;
4. сортирует результат независимо от порядка пакетов и требований.

По умолчанию распознаются только корректные даты `YYYY-MM-DD` в тексте срока.
Самая ранняя дата становится `dueDate`. Свободные формулировки вроде «ежегодно»
не интерпретируются эвристически и возвращаются в
`unresolvedDeadlineRequirementIds`. Для предметных календарей можно передать
`resolveDueDate`, не меняя модель и порядок очереди.

Приоритеты идут в порядке `overdue`, `today`, `soon` (следующие семь дней),
`planned`. При равном приоритете записи сортируются по дате, затем обязанности
раньше возможностей и, наконец, по устойчивому идентификатору требования.

Автоматическая генерация не означает, что действие выполнено, и не является
юридической рекомендацией. В `ActionItem` сохраняются исходное основание,
результат применимости и признак модельного источника для отображения в UI.
