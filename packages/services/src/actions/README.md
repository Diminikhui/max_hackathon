# Очередь действий (4-01)

`ActionQueueService` строит очередь поверх результата `ChecklistService`:

1. берёт только требования со статусом `applies` и непустым `deadline`;
2. получает дату исполнения (`resolveDue`);
3. назначает приоритет относительно даты расчёта `asOf`;
4. сортирует результат независимо от порядка пакетов и требований.

```ts
const queue = await new ActionQueueService({ checklists }).build(companyId, { asOf: "2026-09-28" });
// queue.actions — действия с датой; queue.undated — применимые требования без даты с причиной
```

## Откуда берётся дата

В контракте `Requirement.deadline` — свободный текст («ежедневно», «до допуска к
работе», «при каждой продаже»). Сервис не разбирает его эвристикой и не использует LLM.
Дата появляется только двумя способами:

1. **Явная дата `YYYY-MM-DD` в тексте срока** — берётся самая ранняя (`dueSource: "deadline_text"`).
2. **Модельный календарь сроков** [`calendar.ts`](calendar.ts) (`dueSource: "calendar"`):
   правило для каждой записи федеральных пакетов общепита и автосервиса v1, разобранное
   человеком из текста срока. Дату получает только ежедневное действие (на дату расчёта,
   с конкретным `dueAction`).

Остальные применимые требования попадают в `undated` с причиной:

| `reason` | Значение |
|---|---|
| `event` | Срок наступает при событии; `detail` — какое событие |
| `continuous` | Требование действует постоянно |
| `periodic_without_last_date` | Периодическое действие; нужна дата последнего исполнения, её нет в фактах |
| `calendar_outdated` | Правило написано для другой версии пакета — дата не выдаётся, пока календарь не сверят |
| `not_in_calendar` | Для записи нет правила |

Тест сверяет календарь с опубликованными пакетами: запись со сроком без правила или правило
без записи ломают сборку. Новый пакет или версия требуют дополнить `DEFAULT_DUE_CALENDAR`.
Свой календарь или предметный вычислитель можно передать через `resolveDue`.

## Приоритет и порядок

Приоритеты идут в порядке `overdue`, `today`, `soon` (следующие семь дней), `planned`.
При равном приоритете — по дате, затем обязанности раньше возможностей, затем по
пакету и идентификатору требования.

Автоматическая генерация не означает, что действие выполнено, и не является
юридической рекомендацией. В записях сохраняются исходный текст срока, основание,
результат применимости и признак модельного источника для отображения в UI (4-02).
