# Промпт классификации нормативных документов

`REGULATORY_IMPACT_PROFILE` расширяет ядро K-19a четырьмя видами воздействия:

- `new_obligation` — вводится новая обязанность;
- `changed_obligation` — меняется существующая обязанность;
- `removed_obligation` — обязанность отменяется;
- `new_opportunity` — появляется право или возможность, но не рекомендация воспользоваться ею.

Пустой `impactTypes` означает, что данных для выбора недостаточно. Это безопаснее, чем добавлять
в схему пятый псевдотип или угадывать. `effectiveDate` содержит только явно указанную дату вступления
в силу, а `industry` ограничен направлениями MVP и межотраслевым значением.

Провайдер должен передавать сообщения из `buildClassificationPrompt` с сохранением ролей:
системное сообщение содержит неизменяемые правила, пользовательское — JSON-конверт недоверенного
документа. Нельзя конкатенировать текст документа с системным сообщением. Даже после классификации
результат остаётся автоматическим черновиком и требует проверки человеком; применимость к компании
вычисляет механизм правил, а не модель.
