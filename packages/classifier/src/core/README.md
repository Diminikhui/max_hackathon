# Ядро классификатора K-19a

`classifyDocument(document, provider?)` принимает документ с URL первоисточника. Без провайдера используется `TemplateProvider`: детерминированно берёт заголовок, не читает текст документа и не делает юридического вывода. Результат всегда содержит URL из входа, `automated: true` и `reviewRequired: true`. Для модельных документов и тестового двойника выставляется `isModel: true`.

`LlmProvider.generate(request)` возвращает недоверенное значение. Ядро проверяет его по `DRAFT_SCHEMA` (JSON Schema 2020-12, только непустое `summary`). При ошибке провайдера или несоответствии схеме используется детерминированный шаблон; в результате видны `provider: "template"` и `usedFallback: true`. `TestDoubleProvider` нужен для контрактных тестов без внешнего сервиса.

Третий аргумент `classifyDocument` — `ClassifierProfile<TDraft>`: расширенная строгая схема и функция шаблонного ответа с теми же полями. Проверка ответов обоих провайдеров одинаковая. Расширенный ответ доступен в `result.draft`, а `result.summary` остаётся удобным общим полем. K-19d может добавить поля классификации, не меняя этот модуль.

`request.document.text` — недоверенные данные; реализация провайдера должна передавать их отдельно от системных инструкций. Промпты, четыре типа воздействия, отрасль и срок вступления — поток K-19d. Провайдеры GigaChat и локальной модели — K-19b/K-19c. Этот черновик не определяет применимость нормы к компании: юридически значимые правила публикуются после проверки человеком и вычисляются механизмом правил.

Проверка: `pnpm --filter @max-hackathon/classifier test`.

## Таймаут провайдера

Если провайдер не ответил за `timeoutMs` (по умолчанию 30 000 мс, задаётся в профиле), классификатор откатывается на детерминированный шаблон: `provider: "template"`, `usedFallback: true`. Так зависший GigaChat или локальная модель не лишают пользователя ответа.
