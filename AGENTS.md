# Инструкции для Codex

Перед работой обязательно прочитай [TEAM_GUIDE.md](TEAM_GUIDE.md), Issue текущей задачи и связанные архитектурные решения.

## Порядок работы

1. Проверь ветку и состояние рабочего дерева.
2. Убедись, что текущий worktree не используется другим агентом.
3. Сформулируй проверяемый результат задачи.
4. Изучи существующий код и внеси минимальное связное изменение.
5. Выполни проверки, подходящие изменению.
6. Покажи пользователю изменённые файлы, результаты проверок и оставшиеся риски.

## Рабочие потоки

Работа идёт потоками из [docs/roadmap.md](docs/roadmap.md). Бери только Issue с label `ready` и назначь его на себя перед началом. Меняй только зону файлов из Issue. Правила выбора, зависимостей, контрактов и завершения потока — в [docs/agents/work-packages.md](docs/agents/work-packages.md). Допустим только ИИ уровня GigaChat или локальной модели ([ADR-0001](docs/decisions/0001-llm-provider-policy.md)); моки всегда помечай модельными.

Не создавай и не отправляй коммит, не открывай и не объединяй Pull Request, если пользователь не поручил это явно. Не изменяй настройки внешних сервисов без поручения.

Для проектных решений используй `docs/decisions/`. Для новых переменных окружения обновляй `.env.example`, не добавляя реальных значений.
