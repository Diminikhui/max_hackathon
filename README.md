# «Пульс» — персональные требования и возможности бизнеса в MAX

«Пульс» помогает предпринимателю не пропускать применимые изменения: строит профиль компании по ИНН, сопоставляет его с правилами и мерами поддержки, а затем отправляет короткие уведомления в MAX со ссылкой на официальный источник.

## Статус проекта

Репозиторий находится в стадии сборки MVP для хакатона MAX. Уже реализованы доменная модель, хранение, вычисление применимости, модельные данные и инфраструктура. Пользовательский сценарий бота, API и мини-приложения ещё объединяется; их текущие entrypoint-файлы не следует считать готовым продуктом.

Локальная разработка не требует токена MAX и не принимает события от платформы. Выданный организаторами бот работает только на VPS.

## Сценарий MVP

1. Пользователь открывает бота или мини-приложение и вводит ИНН.
2. Сервис находит сведения о компании и предлагает подтвердить профиль: регион, ОКВЭД, размер и численность.
3. Движок применимости выбирает только подходящие компании требования и меры поддержки.
4. Пользователь получает краткую карточку: что изменилось, почему это относится к нему, что сделать и где прочитать первоисточник.
5. Настройки профиля и уведомлений можно изменить в мини-приложении.
6. Для демонстрации модельное изменение запускается отдельным видимым действием и всегда помечается как модельное.

Продукт не заменяет юриста или бухгалтера и не выдаёт модельные данные за официальные.

## Архитектура

```text
MAX bot / Mini App
        │
        ▼
  miniapp-api ─────► PostgreSQL
        │                ▲
        ▼                │
      worker ──► профиль / правила / применимость
        │
        ├────► официальные источники
        └────► template | GigaChat | локальная модель
```

| Компонент | Назначение |
| --- | --- |
| `apps/bot` | диалог с пользователем и доставка сообщений в MAX |
| `apps/miniapp-api` | внутренний API мини-приложения |
| `apps/miniapp` | интерфейс профиля и настроек |
| `apps/worker` | фоновые загрузки, сопоставление и доставка |
| `packages/domain` | профиль предприятия и доменные типы |
| `packages/storage` | схема и репозитории данных |
| `packages/applicability` | вычисление применимости правил |
| `packages/classifier` | классификация и объяснение результата |
| `data/` | фикстуры, rule packs и модельные изменения |

Подробности: [архитектура](docs/architecture.md) и [ADR](docs/decisions/README.md).

## Требования

- Git;
- Docker с Compose v2 — рекомендуемый способ запуска;
- либо Node.js 24 LTS и pnpm 11 для запуска без Docker.

## Быстрый локальный запуск

Из чистого клона:

```bash
git clone https://github.com/Diminikhui/max_hackathon.git
cd max_hackathon
cp .env.example .env
docker compose up --build --wait
```

Значения из `.env.example` подходят для локального контура. После запуска:

| Сервис | Адрес с настройками по умолчанию |
| --- | --- |
| Мини-приложение | <http://localhost:4173> |
| API мини-приложения | <http://localhost:3000> |
| PostgreSQL | только внутри сети Compose, порт `5432` |
| bot / worker | внешние порты не публикуются |

Порты с хоста меняются через `MINIAPP_PORT` и `MINIAPP_API_PORT`.

### Почему локально не нужен MAX

Compose принудительно запускает бота с пустым `MAX_BOT_TOKEN` и `MAX_EVENTS_ENABLED=false`. Поэтому локальная среда не конфликтует с выданным ботом и не получает реальные события. Токен хранится только на VPS согласно [ADR-0003](docs/decisions/0003-issued-bot-and-hackathon-contour.md).

### Запуск без Docker

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

Проверки репозитория:

```bash
pnpm lint
pnpm typecheck
./scripts/verify-repository.sh
```

Для такого режима PostgreSQL и процессы приложений запускаются отдельно. Тесты хранилища используют изолированную PGlite и не требуют внешней базы.

## Переменные окружения

Полный безопасный шаблон находится в [.env.example](.env.example). Основные переменные:

| Переменная | Назначение | Локальное значение |
| --- | --- | --- |
| `DATABASE_URL` | подключение к PostgreSQL | задано для Compose |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | локальная база | несекретные dev-значения |
| `MINIAPP_PORT` | порт UI на хосте | `4173` |
| `MINIAPP_API_PORT` | порт API на хосте | `3000` |
| `MAX_BOT_TOKEN` | токен выданного бота | пусто; только VPS |
| `MAX_EVENTS_ENABLED` | разрешение принимать события MAX | локально `false` |
| `LLM_PROVIDER` | `template`, GigaChat или локальная модель | `template` |
| `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE` | доступ к GigaChat | не нужен для `template` |
| `LOCAL_LLM_URL`, `LOCAL_LLM_IMAGE` | URL и образ локального runtime | опционально |
| `MAX_CA_CERT_PATH`, `MAX_CA_CERT_SHA256` | путь и проверенный отпечаток корневого сертификата | опционально |

Не коммитьте `.env`, токены, пароли или ключи. Проверка TLS не должна отключаться.

## Источник профиля предприятия

Целевой официальный источник — [Единый реестр субъектов МСП ФНС](https://rmsp.nalog.ru/). В профиль входят как минимум ИНН, регион, основной и дополнительные ОКВЭД, категория МСП и доступная численность. До подключения промышленной загрузки используются тестовые фикстуры.

Ограничения источника:

- ФНС публикует массовые открытые данные крупными XML-архивами, а не гарантированный публичный API поиска по одному ИНН;
- сведения обновляются периодически и могут отставать от текущего состояния компании;
- отсутствие компании или поля в снимке не означает ошибку пользователя;
- полученные значения пользователь должен подтвердить и при необходимости исправить;
- ИНН и сведения профиля нельзя писать в открытые логи.

Подробнее: [исследование реестров МСП](docs/research/k04b-msp-registers.md) и [требования безопасности](docs/security.md).

## Правила, данные и модельные изменения

Rule pack хранит условие применимости, срок действия, объяснение и обязательную ссылку на источник. Движок сопоставляет правило с подтверждённым профилем, а шаблонный классификатор позволяет получить воспроизводимый результат без внешнего ИИ.

Данные для демонстрации находятся в `data/fixtures`. Они не являются реальными нормативными изменениями. Модельная запись должна явно содержать маркировку «модельное» в интерфейсе и сообщении.

Запланированный демонстрационный контракт:

- видимая кнопка **«🧪 Показать пример изменения (модельное)»**;
- явное подтверждение пользователя;
- создание одной воспроизводимой модельной версии;
- повторный запуск не создаёт дубликаты;
- карточка и уведомление сохраняют маркировку «модельное».

Кнопка и сквозной сценарий ещё не подключены в текущем `main`; готовые фикстуры и ожидаемое различие версий описаны в [README набора K-28](data/fixtures/k28-README.md).

## Интеграции и деградация

| Интеграция | Для чего нужна | Поведение без неё |
| --- | --- | --- |
| MAX | ввод ИНН и уведомления | локальная разработка и тесты продолжают работать без событий |
| Реестр МСП ФНС | фактический профиль | используются фикстуры и ручное подтверждение |
| GigaChat | дополнительная классификация | `LLM_PROVIDER=template` даёт детерминированный результат |
| Локальная модель | автономный экспериментальный runtime | профиль Compose не запускается по умолчанию |
| PostgreSQL | постоянное хранение | в тестах используется PGlite |

GigaChat-провайдер подключается отдельной задачей; до её завершения и live-проверки с ключом рабочим режимом остаётся `template`.

Локальная модель не входит в образы приложения. При наличии совместимого runtime она запускается отдельным профилем:

```bash
docker compose --profile local-model up --build
```

Веса сохраняются в томе `local-model-data`.

## API и внешний контур

`miniapp-api` предназначен для собственного мини-приложения и не является публичным API для сторонних клиентов. Контракт стабилизируется вместе со сквозным сценарием; до появления спецификации нельзя полагаться на пути и формат ответов.

На VPS Nginx завершает TLS на портах `80/443` и проксирует мини-приложение. SSH использует порт `22`; внутренние сервисы и база наружу не публикуются. Инструкция: [развёртывание](docs/deploy.md).

## Безопасность и приватность

- секреты передаются только через окружение или хранилище секретов VPS;
- сертификат НУЦ Минцифры размещается в `certs/russian_trusted_root_ca.crt` и передаётся процессу Node.js через `NODE_EXTRA_CA_CERTS`;
- запрещено использовать `NODE_TLS_REJECT_UNAUTHORIZED=0` и аналоги;
- логи не должны содержать токены, ключи, полный ИНН или сырой профиль;
- каждое содержательное утверждение о требовании сопровождается официальной ссылкой;
- сгенерированное резюме — справочная навигация, а не юридическая консультация.

См. [certs/README.md](certs/README.md) и [требования безопасности](docs/security.md).

## Известные ограничения MVP

- интерфейсы бота, API и мини-приложения ещё собираются в единый сценарий;
- массовая загрузка реестра МСП и регулярное обновление источников не завершены;
- точность зависит от полноты подтверждённого профиля и формализованных правил;
- модельный триггер предназначен только для демонстрации;
- внешний LLM необязателен и не является источником нормативных фактов;
- нагрузочная, длительная эксплуатационная и юридическая валидация находятся за пределами хакатонного MVP.

## Остановка и очистка

Остановить сервисы, сохранив данные:

```bash
docker compose down
```

Полностью удалить локальные тома, включая PostgreSQL и веса локальной модели:

```bash
docker compose down -v
```

Вторая команда необратимо удаляет локальные данные проекта.
