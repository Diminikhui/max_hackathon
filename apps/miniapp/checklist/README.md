# Экран перечня (2-03)

Экран создаёт сессию через `POST /api/v1/session` с `initData` из MAX Bridge, затем загружает
`GET /api/v1/checklist`. Токен сессии хранится только в памяти компонента.

Показываются фильтры по статусам применимости с числом записей (статусы без записей скрыты), раскрываемая
карточка и кнопка первоисточника. Закрытая карточка — заголовок и статус; открытая — подписанные блоки «Суть
требования», «Срок» (целиком), «Почему такой статус», «Основание» (акт и статья), дата проверки (#372). Ссылка
открывается через Bridge из `useApp().openLink`.

Вне MAX экран использует явно помеченный модельный перечень, содержащий по одной записи каждого
статуса. Это позволяет проверять web/mobile-вёрстку без настоящего `initData` и компании.
