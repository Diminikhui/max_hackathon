# «Простым языком» (2-22)

Кнопка «💬 Простым языком» на карточке требования (K-24b) пересказывает **уже вычисленный** результат применимости (ADR-0001, п. 4). Статус, причину и первоисточник выводит бот; модель только объясняет готовые шаги простыми словами.

## Что получает модель

Только вычисленный результат (ADR-0001, п. 6): шаги «факт» и «условие» из `applicability.explanation` — их строит `buildExplanation` по решающим листьям `decisiveLeaves` (`packages/rules/src/explain/`), — вид и название записи. Текст документов, ввод пользователя, описание записи и статус в запрос не попадают. Длина каждой строки и число шагов ограничены.

## Провайдеры

| `LLM_PROVIDER` | `GIGACHAT_AUTH_KEY` | Что отвечает |
|---|---|---|
| не задан, `template`, любое другое | — | шаблон без ИИ: «📝 Пересказ по шаблону, без ИИ» |
| `gigachat` | пустой | шаблон; в журнале `app.explain.enabled` с `fallbackReason: missing_key` |
| `gigachat` | задан | GigaChat: «🤖 Пересказ модели GigaChat — проверьте по источнику» |

У GigaChat свой промпт пересказа `RETELL_SYSTEM_PROMPT` (опция `prompt` у `GigaChatProvider`), а не промпт классификации документов. Ответ проходит `classifyDocument` (K-19a) со строгой схемой `RETELL_SCHEMA`: `summary` и массив `points`, без дополнительных полей. Массив стоит последним и ограничений длины в схеме нет намеренно: живая проверка 29.09 показала, что иначе GigaChat в строгом режиме обрывает JSON. Длину (1500 символов, до трёх пунктов) ограничивает бот; пересказ со служебным форматом (`{}`, поля классификатора) заменяется шаблоном. Если только проверка статуса/применимости отклоняет первый ответ, бот ровно один раз повторяет запрос к тому же провайдеру с дополнительной системной инструкцией; текст отклонённого ответа в повтор не передаётся. Повторный ответ снова проходит схему и защитные проверки, иначе показывается шаблон. Сбой, таймаут 8 секунд или ответ не по схеме сразу ведут к шаблону. Для GigaChat в чате отключены повторы после 429: пользователь ждёт ответа.

## Подключение

```ts
createBotApp({ ...deps, explain: { provider: explainProviderFromEnv(process.env).provider } });
```

Без `explain` кнопки нет, а payload `explain:<requirementId>` не обрабатывается. В worker зависимость передаётся только при `BOT_FEATURES` со словом `explain` (`apps/worker/src/app/config.ts`).

## Включение на сервере

Ключ GigaChat можно добавить последним шагом — без него фича работает на шаблоне.

1. В `/etc/max-hackathon/compose.env` добавить `explain` в `BOT_FEATURES` (например, `BOT_FEATURES=explain`) и перезапустить worker. Кнопка появится, ответы — по шаблону.
2. Когда ключ получен: там же задать `GIGACHAT_AUTH_KEY=<ключ>` и `LLM_PROVIDER=gigachat`, перезапустить worker. В журнале при старте — `app.explain.enabled` с `provider: gigachat` и без `fallbackReason`. Значение ключа не выводится.
3. Живая проверка: открыть карточку, нажать «💬 Простым языком» и убедиться, что ответ помечен «🤖 Пересказ модели GigaChat». Если в журнале `bot.explain.fallback` — модель не ответила, пользователю показан шаблон.

Сертификат НУЦ Минцифры для GigaChat подключается образом (`NODE_EXTRA_CA_CERTS`, см. `Dockerfile`, `certs/README.md`).

## Тесты

`apps/bot/test/flows/explain/` — на модельном двойнике провайдера и модельных данных K-28: без флага, шаблон, успех, сбой, ответ не по схеме, таймаут, один исправляющий повтор после комментария о статусе, отказ второго ответа, пустой ключ. Живой вызов — только вручную на сервере.
