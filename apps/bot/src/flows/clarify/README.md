# Уточняющие вопросы (K-09)

Когда у записей перечня статус «недостаточно данных», бот спрашивает владельца о недостающих фактах. Спрашивает только то, что меняет результат: вопросы строятся из `missingFactKeys` записей «недостаточно данных». Ответ сохраняется заявленным фактом (`kind: "declared"`, `source.system: "user"`) — в боте с пометкой «по вашим словам», — и перечень строится заново.

## Подключение (K-30b)

```ts
const clarify = createClarifyFlow({
  checklist: new ChecklistService({ profiles, requirements }), // K-26, порт ChecklistSource
  companyOf: async (dialogId) => sessions.companyOf(dialogId),  // компания после онбординга K-24a
  profiles: new ProfileService({ source, repository }),          // K-25b, порт FactDeclarer (declare)
  skips: createMemorySkipStore(),                                // необязательно; по умолчанию в памяти
  onDeclared: async (companyId, keys) => {                       // необязательно: пересчёт с событием
    // ProfileRecalculationService (packages/services/src/recalc)
    await recalculation.recalculate(companyId, { changedFactKeys: keys });
  },
});

// Обработчик колбэков: кнопки уточнения идут мимо машины диалога.
if (isClarifyPayload(event.payload)) {
  const reply = await clarify.handle(dialogId, event.payload); // FlowReply
  // сохранить reply.stateOverride как состояние диалога, отправить reply.text и reply.buttons
}

// Под перечнем, если в нём есть «недостаточно данных»:
buttons.splice(-1, 0, clarifyButton()); // «❔ Уточнить данные» перед «🏠 Меню»
```

Кнопки уточнения имеют префикс `c:` и не пересекаются с кнопками машины диалога (`d:`, K-22b) и кнопкой покрытия (`coverage`, K-34). Машина диалога не меняется: пока идёт уточнение, диалог остаётся в `requirement_list`, поэтому «🏠 Меню» под вопросом работает как обычно. Каждый ответ задаёт `stateOverride: "requirement_list"`; если компания неизвестна — `idle` и кнопка «Ввести ИНН».

## Как выбирается вопрос

1. Берутся записи со статусом `insufficient_data` и их `missingFactKeys`. У остальных статусов ответ результат не изменит.
2. Спрашиваются только факты из каталога `CLARIFY_QUESTIONS` — те, что знает владелец: есть ли работники, продажа алкоголя, лицензии, налоговый режим. Факты реестра (ОКВЭД, регион, категория МСП) и численность не спрашиваются: в итоге сказано, что их даёт профиль из реестра.
3. Сначала — вопрос, от которого зависит больше записей; при равенстве — порядок каталога.
4. После каждого ответа перечень строится заново, и следующий вопрос выбирается по новому перечню: вопрос, который перестал влиять на результат, не задаётся.

Для модельной компании K-28 `1600000011` (кафе в Казани) это ровно два вопроса: «Есть ли у вас работники?» и «Продаёте ли вы алкоголь?». После ответов обе записи получают итоговый статус.

## Экраны

| Экран | Что показывает | Кнопки |
|---|---|---|
| Вопрос | Текст вопроса и подсказка, записи, которым нужен ответ, сколько вопросов осталось | варианты ответа, «Пропустить», «← К перечню», «🏠 Меню» |
| После ответа | «✍️ Записали по вашим словам: …», какие записи сменили статус, затем следующий вопрос | как у вопроса |
| Итог | Перечень K-24b с пояснением: всё ли получило итоговый статус, на какие вопросы нет ответа, какие данные бот не спрашивает | номера записей, «❔ Уточнить данные» (если остались вопросы), «🏠 Меню» |

## Тупиков нет

| Случай | Ответ |
|---|---|
| «Пропустить» | Следующий вопрос; пропущенный в этом заходе больше не задаётся |
| Все вопросы пропущены или «← К перечню» | Перечень с пояснением и кнопкой «❔ Уточнить данные» — она начинает заход заново, с пропущенными вопросами |
| Уточнять нечего | Перечень: «у всех записей есть итоговый статус» |
| Кнопка из старого сообщения (нет такого варианта) | Ничего не сохраняется, показывается актуальный вопрос |
| Ответ не сохранился | Сообщение ошибки и тот же вопрос |
| Компания не найдена | «Сначала укажите ИНН», состояние `idle` |

## Ограничения

- Ответы только кнопками. Числа (численность, площадь зала) бот не спрашивает.
- Налоговый режим — один основной; сочетание «патент и УСН» кнопкой не задаётся.
- Ключи фактов из запроса #234 (площадь зала, тип заведения и др.) добавятся в каталог после PR `contract: …`.
- Ответ меняется только новым заходом, пока факт остаётся недостающим. Правка сохранённого ответа — через профиль (мини-приложение).
