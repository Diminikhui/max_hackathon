# Демо-триггер (K-29)

Кнопка «🧪 Показать пример изменения (модельное)» показывает уведомление об изменении без ожидания реального изменения законодательства. Отдельного «демо-уведомления» нет: нажатие публикует заранее подготовленную следующую версию модельного пакета ([data/rulepacks/_demo](../../../../../data/rulepacks/_demo/README.md)) и запускает тот же контур, что при реальном изменении.

```
кнопка ─► публикация k28-model v2 (saveVersion) ─► контур K-30a: событие rulepack_version ─► планировщик K-20a
  ─► политика K-20b ─► шаблон K-23 ─► очередь K-21a ─► уведомление в чат нажатия
       └► ответ на нажатие: что изменилось, почему касается компании, первоисточник, «модельное изменение»
```

## Подключение (K-30b)

```ts
import {
  createDemoChangeFlow,
  DEMO_CHANGE_CALLBACK_PAYLOAD,
  DEMO_PACK_FILE,
  DemoRecipientDirectory,
  demoChangeButton,
  loadDemoPack,
} from "./flows/demo/index.js";

// Один экземпляр справочника — у сценария и у контура: так уведомление находит чат нажатия.
const recipients = new DemoRecipientDirectory(onboardingRecipients); // основной справочник K-24a — необязателен
const pipeline = new NotificationPipeline({ profiles, notifications, recipients, history });

const demoFlow = createDemoChangeFlow({
  pack: await loadDemoPack(join(repoRoot, DEMO_PACK_FILE)),
  requirements,                       // RequirementRepository (K-10b)
  checklist: new ChecklistService({ profiles, requirements }), // K-26
  companyOf: (dialogId) => sessions.companyOf(dialogId),       // K-24a
  recipients,
  runNotifications: () => runRulepackNotifications({ requirements, events, pipeline }), // K-30a
  notifications,                      // NotificationRepository (K-10c)
});

// Колбэк с payload DEMO_CHANGE_CALLBACK_PAYLOAD обрабатывается вне машины диалога, как «Что проверяется» (K-34):
const reply = await demoFlow.handle({ dialogId, chatId });
```

Кнопку `demoChangeButton()` показывают меню (K-24a) и перечень. Для работы в хранилище должна быть опубликована версия 1 пакета `k28-model` (`data/fixtures/k28-rulepack-v1.json`), а профили модельных компаний K-28 — загружены.

## Поведение

| Случай | Ответ |
|---|---|
| Изменение касается компании | Что изменилось, почему касается (факты и условия из объяснения K-16), первоисточник, «уведомление приходит в этот чат», кнопка «Открыть карточку» |
| Повторное нажатие | Тот же ответ; версия уже опубликована, переход обработан — второго уведомления нет |
| Кнопку раньше нажали в другом чате для той же компании | Тот же ответ, но «уведомление уже создано для чата, где кнопку нажали первым» |
| Изменение не касается компании | Почему не касается и подсказка: модельный ИНН `7700000016` |
| Компания не выбрана | «Сначала укажите ИНН» и кнопка «Ввести ИНН» (`stateOverride: idle`) |
| Версии 1 пакета нет в хранилище | «Демонстрация сейчас недоступна»; ничего не публикуется: первая публикация пакета уведомлений не даёт |

Все ответы помечены модельными и содержат пометку об автоматической обработке. Демо-триггер публикует только модельный пакет: `parseDemoPack` отказывается от файла, где пакет или запись не помечены `isModel`.

Кнопка «Открыть карточку» **по умолчанию скрыта** и включается флагом `BOT_FEATURES=cards`: пока корень сайта на сервере отдаёт страницу проверки K-05b, а не мини-приложение, она открывает технический JSON (Issue #347). Когда мини-приложение включено на корне, добавьте `cards` к `BOT_FEATURES`. Кнопка имеет тип MAX `open_app` и передаёт непрозрачный `requirement_<UTF-8 hex id>` в связанное мини-приложение `t214_hakaton_max_bot`. Payload не содержит ПДн. Сам текст ответа остаётся понятным без открытия мини-приложения: название, применимость, причины и первоисточник уже находятся в сообщении.

## Проверка

- `apps/bot/test/flows/demo/` — сценарий на фейковых портах и совпадение подготовленной версии с фикстурой K-28 v2.
- `apps/worker/test/notify/demo-trigger.test.ts` — сквозной прогон через настоящий контур K-30a, хранилище (PGlite) и модельный отправитель: уведомление приходит в чат нажатия, повтор не создаёт дубль, ключ уведомления совпадает с ключом контура.

## Ограничения

- **Справочник чатов в памяти.** После перезапуска бота следующее нажатие запишет чат заново. Если контур K-30a работает в отдельном процессе worker и успеет обработать переход раньше бота, уведомление не найдёт чат (`noRecipient`) и ответ скажет «уведомление не создано». Поэтому прогон контура запускает сам сценарий сразу после публикации; сборка K-30b должна использовать тот же `DemoRecipientDirectory` или постоянный справочник K-24a.
- **Демо одноразово на стенд.** После первой публикации пакет остаётся в версии 2; все следующие нажатия показывают тот же результат. Чтобы показать уведомление ещё раз «с нуля», стенд пересоздают с версией 1.
- Ключ уведомления (`demoNotificationKey`) повторяет формат dedupKey планировщика K-20a. Если формат изменится, сквозной тест в worker упадёт.
